# Развертывание на Kubernetes в Yandex Cloud

Дата создания: 12.03.2026
Статус: Принято

## Контекст

Платформа включает несколько контейнеров: Frontend (Nginx + SPA), Realtime Sync Service, API Gateway/LMS, Hint Service, PostgreSQL, Redis. Требования к развертыванию: поддержка горизонтального масштабирования Realtime Sync Service, TLS для всех соединений, возможность сворачивания и обновления сервисов без простоя, ориентация на on-premises или суверенное развертывание в российской инфраструктуре.

Среды развертывания: dev (локальная разработка), test (проверка перед релизом), production.

## Рассмотренные варианты

Docker Compose как единственная среда. Подходит для dev и test, но не обеспечивает механизмов горизонтального масштабирования, health checks с автоматическим перезапуском и управления секретами в production.

Kubernetes в собственном дата-центре. Требует полноценной инфраструктуры администрирования кластера. Для MVP избыточно.

Managed Kubernetes на зарубежных провайдерах (GKE, EKS, AKS). Не соответствует требованию суверенного развертывания и ограничениям заказчика.

Managed Kubernetes в Yandex Cloud (Yandex Managed Service for Kubernetes). Российский провайдер с managed-сервисом, совместимым со стандартным Kubernetes API. Поддерживает Container Registry, Ingress с TLS, интеграцию с Managed PostgreSQL и Managed Redis.

## Решение

Три среды развертывания:

Dev: Docker Compose. Все сервисы запускаются одной командой docker compose up. PostgreSQL и Redis запускаются как контейнеры в compose-сети. Разработчик работает локально без доступа к облаку.

Test: Kubernetes namespace test в Yandex Cloud. CI/CD pipeline собирает образы, публикует их в Yandex Container Registry и применяет манифесты к namespace test. Используется для интеграционных и E2E-тестов.

Production: Kubernetes namespace production в Yandex Cloud. Managed PostgreSQL и Managed Redis вынесены за пределы кластера как managed-сервисы Yandex Cloud. Nginx Ingress обеспечивает TLS-терминацию. Горизонтальное масштабирование Realtime Sync Service через HorizontalPodAutoscaler.

Конфигурация сервисов передается через Kubernetes ConfigMap и Secret. JWT-секрет и строки подключения к PostgreSQL и Redis хранятся в Secret.

## Обоснование

Kubernetes обеспечивает механизмы, которые необходимы для production: health checks с автоматическим перезапуском упавшего контейнера, rolling update без простоя, ресурсные лимиты предотвращающие монополизацию ресурсов одним сервисом, горизонтальное масштабирование через HPA.

Yandex Cloud выбран как российский провайдер, соответствующий требованию суверенного развертывания. Managed Kubernetes освобождает от администрирования control plane. Yandex Container Registry интегрирован с Managed Kubernetes для авторизации при pull образов.

Разделение dev/test/prod по средам развертывания соответствует стандартной практике и позволяет проводить интеграционные тесты в среде, максимально приближенной к production, не затрагивая production-данные.

Managed PostgreSQL и Managed Redis в production выведены за пределы кластера: они управляются Yandex Cloud с автоматическим резервным копированием, мониторингом и failover. Это снижает операционную нагрузку.

## Последствия

Переход с Docker Compose (dev) на Kubernetes (prod) требует, чтобы сервисы не содержали жестко заданных IP-адресов или hostname. Все адреса сервисов передаются через переменные окружения.

Kubernetes-манифесты хранятся в репозитории под системой контроля версий. Обновление производственного окружения выполняется через CI/CD pipeline, а не вручную.

## Риски

Новые участники команды могут не иметь опыта работы с Kubernetes. Снижение риска: полная инструкция по dev-окружению через Docker Compose достаточна для повседневной разработки; Kubernetes требуется только при деплое.

Стоимость Managed Kubernetes в Yandex Cloud может быть значимой для учебного проекта. Снижение риска: минимальная конфигурация кластера для MVP, масштабирование только по мере роста нагрузки.

## Оценка результативности

Инфраструктура считается корректно настроенной, если CI/CD pipeline успешно деплоит обновления без ручных операций, health checks обеспечивают автоматический перезапуск упавших подов, все внешние соединения используют TLS, и Realtime Sync Service масштабируется горизонтально без потери активных сессий.
