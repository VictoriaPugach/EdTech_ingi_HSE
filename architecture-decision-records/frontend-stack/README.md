# Выбор технологического стека фронтенда

Дата создания: 24.01.2026
Статус: Принято

## Контекст

Фронтенд платформы должен обеспечить совместное редактирование кода с подсветкой синтаксиса, отображение курсоров и имен участников в реальном времени, всплывающие педагогические подсказки привязанные к строкам кода, список участников сессии и индикатор состояния подключения. Пользователи: дети 10-14 лет и преподаватели. Основной сценарий: десктопный браузер. Язык анализа в редакторе: Python с возможностью расширения.

## Рассмотренные варианты

Vue 3 + Monaco Editor обеспечивает полноценный редактор с поддержкой Language Server Protocol. Monaco является ядром VS Code, что дает широкие возможности, но его интеграция с Yjs потребовала бы написания собственного CRDT-провайдера. Размер бандла Monaco значителен.

React + CodeMirror 6 предоставляет гибкий редактор с официальным биндингом Yjs (y-codemirror.next) и декларативной архитектурой расширений. CodeMirror 6 легче Monaco и лучше подходит для кастомизации интерфейса под детскую аудиторию.

React + Ace Editor. Ace не поддерживает современную расширяемую архитектуру CodeMirror 6. Официального Yjs-биндинга нет.

## Решение

Фронтенд построен на React 18 с TypeScript. Редактор кода реализован на CodeMirror 6. Интеграция с Yjs выполнена через y-codemirror.next. Стилизация использует TailwindCSS. Сборка и dev-сервер через Vite.

Структура компонентов:

- CodeEditor: обертка над CodeMirror 6 с подключением Y.Text и awareness-провайдера;
- SessionParticipants: список участников с индикаторами присутствия;
- HintPanel: отображение подсказки привязанной к строке кода;
- ConnectionStatus: визуальный индикатор состояния WebSocket-соединения;
- SessionControls: создание сессии, вход по invite-коду.

## Обоснование

React 18 выбран как наиболее распространенная библиотека для построения интерактивных SPA с устоявшейся моделью хуков. Concurrent features React 18 позволяют правильно расставить приоритеты обновлений: изменения от локального ввода применяются немедленно, обновления awareness менее приоритетны.

TypeScript обязателен для проекта, где типы API-контрактов совместного редактирования и формат JSON-подсказок должны быть явно определены и проверяться на этапе компиляции. Это снижает вероятность ошибок интеграции между компонентами.

CodeMirror 6 выбран вместо Monaco по трем причинам. Первая: официальный Yjs-биндинг исключает написание провайдера. Вторая: расширения CodeMirror 6 позволяют добавить custom widget для отображения подсказки прямо в теле редактора, рядом со строкой с ошибкой. Третья: меньший размер бандла улучшает время первой загрузки страницы, что важно для пользователей с нестабильным соединением.

TailwindCSS обеспечивает быстрое прототипирование интерфейса без написания кастомных CSS-файлов. Утилитарный подход снижает риск конфликтов стилей в компонентах редактора, где CodeMirror 6 управляет своей DOM-структурой самостоятельно.

## Последствия

Решение зафиксировать stack на React означает, что серверный рендеринг и SEO не требуются для данного типа приложения. SPA деплоится как статические файлы за Nginx Ingress в Kubernetes.

Версии React и CodeMirror фиксируются. Обновление мажорной версии CodeMirror потребует проверки совместимости с y-codemirror.next.

## Риски

Зависимость от y-codemirror.next как от пакета с активной разработкой. Снижение риска: фиксация версии в package.json и проверка совместимости при обновлении Yjs.

Кастомизация CodeMirror 6 для детской аудитории требует доработки тем и шрифтов. Это операционная задача на этапе разработки, а не архитектурный риск.

## Оценка результативности

Фронтенд считается реализованным корректно, если в E2E-тестах Playwright подтверждается одновременное редактирование двумя клиентами с конвергенцией документа, отображение подсказки при синтаксической ошибке и восстановление соединения без потери текста.
