# Hint Service (BC-2) — педагогические подсказки

Микросервис, который анализирует код ученика и формулирует **дружелюбные подсказки
для детей** — без технического жаргона, рядом с местом ошибки. Отдельный сервис на
Python выбран потому, что задача — анализ кода (AST), а в экосистеме Python для этого
лучшие инструменты (см. ADR `hint-service-python`, `ast-first-hints`).

## Что делает

Принимает исходный код, находит типовые ошибки начинающих и возвращает для каждой
короткое объяснение «по-человечески» + где она в коде + как её показать в редакторе.

```
POST /api/hints
{ "code": "print(\"Hi\"", "language": "python", "userAge": 11 }

200 OK
{
  "hints": [{
    "errorType": "syntax/unmatched_paren",
    "message": "Похоже, не хватает закрывающей скобки ). Найди парную и добавь её.",
    "location": { "line": 1, "column": 11 },
    "visualCue": "tooltip"
  }],
  "processingTimeMs": 3
}
```

## Как устроено (конвейер)

```
код ──▶ Analyzer (AST) ──▶ список ошибок ──▶ Generator (шаблоны) ──▶ подсказки
```

1. **Analyzer** (`src/analyzer/`)
   - `parser.py` — строит **AST через Tree-sitter** (грамматики Python/JavaScript).
     Tree-sitter устойчив к некорректному коду: вместо падения вставляет узлы
     `ERROR`/`MISSING`, что и нужно для разбора кода «в процессе набора».
   - `detector.py` — обходит дерево и распознаёт ошибки:
     - синтаксис: незакрытые `()`, `[]`, кавычки, пропущенное `:`;
     - семантика (Python): использование необъявленной переменной (грубый scope-анализ).
   - `py_syntax.py` — для Python дополнительно прогоняет код через стандартный
     **компилятор `compile()`** (без выполнения!) и ловит `SyntaxError`/`IndentationError`
     с точными строкой/столбцом. Это покрывает длинный хвост ошибок (отступы,
     `print` без скобок, незакрытые строки и т. п.) точнее, чем эвристики по дереву.

2. **Generator** (`src/generator/`)
   - `templates.py` — детерминированные шаблоны подсказок, адаптированные под возраст
     (для младших — образные формулировки, для старших — короткие). Принципы (ФТ-8):
     ≤150 символов, без слов «ошибка/неверно», без жаргона (AST/токен/парсер).
   - `service.py` — связывает: ошибка → текст + способ показа (`visualCue`).

3. **API** (`src/main.py`) — FastAPI: `POST /api/hints`, `GET /health`, `GET /docs`.

## Покрываемые ошибки (Python)

| Тип | Пример | Подсказка ребёнку |
|-----|--------|-------------------|
| `syntax/unmatched_paren` | `print("Hi"` | не хватает `)` |
| `syntax/unmatched_bracket` | `nums = [1, 2` | не хватает `]` |
| `syntax/unmatched_quote` | `s = "hello` | кавычка не закрыта |
| `syntax/missing_colon` | `if x > 0` | нужно `:` после `if/for/def` |
| `syntax/invalid_indentation` | блок без отступа | строки блока — с одинаковым отступом |
| `semantic/undefined_variable` | `print(y)` без `y = …` | имя ещё не объявлено |

`print` в стиле Python 2 (`print "x"`) и другие синтаксические ошибки распознаются
через `compile()` и снабжаются понятным текстом.

## Почему не LLM (пока)

Для MVP подсказки **детерминированы и быстры** (KPI: p95 < 2 c — см. `load-tests/`).
Подключение внешней LLM (например, для перефразирования под возраст) вынесено на
следующий этап; контракт API при этом не меняется.

## Запуск и проверка

```bash
# в составе стенда
docker compose up -d hint-service          # слушает :4002

# тесты и линт
cd apps/hint-service
pytest -q
ruff check src tests && black --check src tests

# нагрузочный замер p95 (TC-08)
node ../../load-tests/hint-api.mjs
```
